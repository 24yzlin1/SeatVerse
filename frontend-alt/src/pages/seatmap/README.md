## 数据与文件

`api.ts` 先请求活动详情，再并行请求场馆静态座位与本场状态；`data.ts` 严格校验编号、容量、坐标、状态覆盖与活动对应关系。3D 原样使用 `[x,y,z]`，平面和 3D 点击均回传同一后端 `seat.id`。坐标单位米，X 向右、Y 向上、Z 向后排。

`session.ts` 独立管理加载、选择、提交与请求代数；`SeatBooking.svelte` 接入会话和登录态；`components/SeatBookingSection.svelte` 保留新版双视图。3D 全馆视角隐藏顶棚和靠近相机的外墙，避免遮挡座位。

请求接口：`GET /events/{id}`、`GET /venues/{id}/seats`、`GET /events/{id}/seats`、`POST /bookings`。公共客户端负责 `/api` 前缀、Authorization 和顶层业务码。提交体仅含 `{eventId,seatIds}`，成功结果校验真实预约编号、票号及精确座位集合。

详情页统计使用 `GET /events/{id}/seat-statistics`，本场预约使用 `GET /bookings/me?eventId=...`。本人预约按服务端状态筛选并支持继续加载，刷新保留已经加载的页数，并按 ID 去重。

## 失败与状态处理

- 本地选择不代表锁座；提交期间冻结编号、阻止重复请求，POST 不自动重试。
- 409 后回源，移除冲突座位，保留仍可预约的选择；刷新失败时阻止再次提交，提供显式刷新。
- 网络失败、非法成功体和 5xx 提示先到“我的预约”核对，不假定预约必然未入库。
- 401 由公共层清会话；旧账号迟到的 401 不能清除新账号。跨标签换账号重新请求本人身份，旧 `/me` 不覆盖新会话。
- 关闭、取消、草稿、开始／结束、满座及状态异常禁止预约；初次加载失败有重试，接口离线不回退模拟数据。
- 活动切换、账号切换与卸载使旧请求失效；旧 POST、详情、预约与票据响应不覆盖当前活动或私有记录。
- 进入、切回前台及每 30 秒刷新座位；创建／取消事件更新相关展示。成功原地展示真实结果，链接“我的预约／电子票”。
