# 场馆选座与真实预约

选座入口为 `#/events/:id/seats`，从活动列表或详情进入。页面读取后端活动、场馆静态座位和本场座位状态，确认后创建实际预约；“我的预约”读取数据库并支持取消、释放座位。3D 和平面选座共用一份服务端数据及本地选择集合。

## 启动

先按 [后端说明](../../../../backend/README.md) 启动 API，再在 `frontend/` 执行：

```powershell
npm ci
npm run dev
```

打开 <http://localhost:5173/#/events>，选择实际活动进入选座。空数据库可运行仓库原有的 `uv run poe seed` 导入后端初始化数据；不要使用 `--reset` 覆盖已有记录。已有活动直接按数据库内容展示。

页面没有模拟数据回退开关。旧的 1001 / 1002 演示地址不再是默认入口；资源不存在、数据异常或接口离线时显示错误和重试。历史选座检查脚本、辅助文件与固定模拟数据已从仓库移除，仅保留在本地忽略路径。

## 数据与提交

复用 `@/common/api` 的请求、鉴权和错误处理，路径函数不重复添加 `/api`：

- `GET /events/{id}`：实际活动、状态、时间和场馆。
- `GET /venues/{venueId}/seats`：`{ items: [{ id, row, number, label, seatType, x, y, z }] }`。
- `GET /events/{id}/seats`：`{ items: [{ seatId, status }] }`。
- `POST /bookings`：发送 `{ eventId, seatIds }`，成功显示服务端返回的预约编号和票号。
- `GET /bookings/me`：读取并合并分页后展示实际预约。
- `POST /bookings/{id}/cancel`：取消本人尚未开始、未签到的预约，后端在一个事务中释放座位并保留取消记录。

静态 `id` 与动态 `seatId` 关联，不以数组下标、排号或座号生成业务编号。适配层校验活动编号、时间、容量、唯一座位及状态覆盖；未知状态不能视为空闲。草稿、关闭、取消、已开始或已结束的活动禁止提交。

选择只是本地意向，不代表锁座。确认时禁止重复点击，POST 不自动重试。冲突与业务失败后重新获取座位，移除失效选择；网络中断且结果未知时提示先查看“我的预约”。活动切换清空选择，旧请求不能覆盖新活动。进入页面、提交后、切回前台及每 30 秒刷新服务器状态。

未登录用户可浏览并选择；登录入口携带当前真实活动路径，登录成功后返回该场选座。登录期间不保留本地选择，需要重新确认座位。

## 文件职责

- `SeatMapPage.svelte`：路由、接口加载、共享选择、提交与刷新控制。
- `api.ts` / `data.ts`：真实请求、数据校验和适配。
- `SeatSelectionPage.svelte`：活动信息、3D / 平面、确认区及服务端坐标明细。
- `SelectedSeatPanel.svelte`：已选清单、移除、清空、确认及禁用原因。
- `SeatScene.svelte` / `VenueScene.svelte`：按需加载的画布、场馆、镜头与交互。
- `SeatPlan.svelte`：原生按钮组成的平面图，默认展开，可局部横向滚动。
- `selection.ts`：共享选择与状态优先级；`seat-layout.ts`：双视图投影。
- `scene-model.ts` / `seat-interaction.ts`：共享模型资源、镜头适配、射线命中与手势区分。
- `@/common/utils/eventAvailability.ts`：列表、详情及选座共用的预约时间与状态规则。

## 固定场馆与坐标

当前版本按项目固定场馆建模。后端预置场馆含 10 排、每排 12 座；所有活动共用静态座位，各自保存动态状态。

3D 原样使用 `position = [seat.x, seat.y, seat.z]`。平面按 `left = (x + 10) / 20`、`top = (z + 4) / 20` 投影，不重新生成坐标。单位为米，X 向右、Y 向上、Z 从舞台指向后排。排座仅用于标识，两个视图的点击均回传同一 `seat.id`。

馆内包含四面墙、顶棚、侧墙格栅与壁灯、幕布、木质舞台、钢琴及过道引导灯。“全馆俯瞰”隐藏顶棚和靠近相机的外墙；拖动、滚轮和按钮支持旋转、缩放、重置。点击命中考虑建筑遮挡，拖动和多指手势不会误选。场景卸载时清理监听、动画及资源。

两个视图读取共享的可选、已预约、本地已选和不可选颜色；已预约、锁定或状态未知的座位不可选。本模块不使用 emoji 图标。

## C-04 已选列表与预约确认区

- 确认卡展示本次实际活动名称、场馆、开始／结束时间和预约状态，与页头读取同一活动和时钟。
- 已选数量与清单来自页面唯一的选择集合；可逐座移除或清空，3D 和平面同步更新。重置视角保留已选座位。
- 按钮复用项目共享的 `Button`、主题和焦点样式。未选座位时，游客与登录用户都不能确认；游客选好座位后可进入登录，并返回本场选座。
- 刷新与提交期间禁用清单修改及确认。提交先复制并冻结本次座位编号，快速重复点击只提交一次；失败后解除等待并保留仍有效的选择。
- 成功后清空本地选择，将实际预约编号、票号与座位直接展示在确认卡内，并将键盘焦点移至成功标题；可进入“我的预约”查询。开始新选择时移除上一笔成功提示。提交错误也在确认卡内显示。
- 桌面确认卡随页面滚动，较长清单可内部滚动；宽度不超过 800px 时提供底部“查看已选与确认”入口，只跳转至确认卡，避免新增第二个提交入口。页面留出底部空间，确认按钮不被快捷入口遮挡。

## 验收

在 `frontend/` 运行 `npm run check:all`；后端运行 `uv run poe check`。前端验证脚本只在本地保留，不加入仓库、包脚本或构建命令；新增接口与适配验证位于被 Git 忽略的 `.local-checks/`。

浏览器检查：实际活动进入 → 登录后返回 → 3D / 平面同步选择 → 确认成功 → 刷新“我的预约”仍有记录 → 取消 → 本场座位恢复可选。还需核对已结束 / 关闭活动禁用、未知编号无模拟回退，以及窄屏确认按钮和局部横向滚动。

2026-11-20 本地已验证上述浏览器流程、实际 120 座与坐标、3D 点击同步、390px 页面无整体横向溢出，最终控制台无 error / warn。并发抢座、整单回滚、权限隔离、取消后重新预约及草稿发布初始化由隔离数据库验证。生产构建仍保留原有 3D 分包超过 500kB 的提示；真实触屏多指手势仍需设备验收。
