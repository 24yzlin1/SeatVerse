# SeatVerse · 前端开发规范

> 技术栈：Svelte 5 + Vite + shadcn-svelte + Tailwind v4 + Threlte（不使用 SvelteKit）
> 类型要求：**严格模式，禁止 `any`，禁止忽略注释**
> 本规范在原《前端开发规范》基础上补充本项目专属约定（路由、状态、接口、3D）。

---

## 一、目录结构与别名

```
src/
├── assets/              # 图片、字体、静态资源
├── common/              # 自定义共享组件与逻辑
│   ├── components/      # 自定义通用组件
│   ├── api/             # 请求客户端、接口函数、错误码常量
│   ├── stores/          # 共享状态（*.svelte.ts）
│   ├── router/          # hash 路由：routes.ts、router.svelte.ts、RouteView
│   └── utils/           # 纯函数工具
├── lib/                 # 可复用库（$lib 别名）
│   └── components/
│       └── ui/          # shadcn-svelte 生成 —— 严禁手动修改
├── pages/               # 路由页面，按模块分目录
└── app.css              # 全局样式入口
```

**别名**

- `@/* -> src/*`
- `$lib/* -> src/lib/*`

**导入**

- 所有文件导入必须使用别名（`@/` 或 `$lib/`），**禁止使用相对路径跨目录引用**。

> `$lib/components/ui` 为 shadcn-svelte 自带组件，**严禁手动修改**。
> 所有自定义通用组件必须放在 `common/components/` 下。

### 页面目录（对应五大模块）

| 模块 | 目录 |
|---|---|
| M1 登录与认证 | `pages/authentication/` |
| M2 活动查看 | `pages/events/` |
| M3 3D 选座与预约 | `pages/seatmap/` |
| M4 我的预约与电子票 | `pages/bookings/`、`pages/tickets/` |
| M5 主办方核验端 | `pages/organizer/` |

## 二、样式规范

### 全局入口

必须包含以下导入与配置：

```css
@import "tailwindcss";
@import "tw-animate-css";
@import "shadcn-svelte/tailwind.css";

@custom-variant dark (&:is(.dark *));
@plugin '@tailwindcss/typography';
```

### 设计令牌

- 所有颜色、圆角等定义在 `:root` / `.dark`，并通过 `@theme inline` 映射为 Tailwind 工具类。
- **组件内禁止硬编码任何颜色值**，必须使用对应的工具类。
- 修改配色时仅需修改 `app.css` 中的 CSS 变量，组件代码无需改动。

### 自定义工具类

在 `@layer components` 或 `@layer utilities` 中定义全局复合类。

### 座位状态配色

座位状态颜色**必须走设计令牌**，不得硬编码：

| 状态 | 语义 | 说明 |
|---|---|---|
| 空闲 | 中性色 | 默认可售 |
| 已预约 | 危险/禁用色 | 不可选 |
| 本地已选 | 主色高亮 | 仅交互态，不写库 |

## 三、组件规范

### 类名书写

所有元素的 `class` 必须使用**数组形式**，每个类名单独字符串，由框架自动拼接。

**示例**

```svelte
<div
  class={[
    "sticky", "top-0", "bg-background/50", "backdrop-blur-xl",
    "flex", "items-center", "justify-between", "border-b", "border-border"
  ]}
/>
```

**条件类**

```svelte
<a
  class={[
    "base", "hover:primary",
    ...(selected ? ["text-primary", "border-primary"] : ["text-muted", "border-transparent"])
  ]}
/>
```

禁止使用字符串拼接或滥用 `class:` 指令。

### 变体管理

使用**查找表**管理不同变体的样式类，便于扩展与维护。

```svelte
<script>
  const baseClasses = ["inline-flex", "items-center", "rounded-sm", "border", "px-2"];
  const variantClassesLut = {
    solid: ["bg-primary", "text-primary-foreground", "border-primary"],
    outline: ["bg-transparent", "text-primary", "border-primary"],
  };
</script>
<span class={[...baseClasses, ...variantClassesLut[variant]]}>
  {@render children?.()}
</span>
```

### Snippet 与插槽

使用 `{@render children?.()}` 渲染默认内容，条件逻辑可配合 `{#snippet}` 复用。

### 组件修改红线

| 目录 | 规则 |
|---|---|
| `$lib/components/ui` | 组件库生成，**严禁手动修改** |
| `common/components/` | 自定义通用组件一律放此处，需封装组件库组件时在此做类型收口 |

## 四、状态管理

使用 Svelte 5 **runes**，不引入第三方状态库。

| 场景 | 用法 |
|---|---|
| 组件内局部状态 | `$state` |
| 派生值 | `$derived`，**不手动同步** |
| 跨页面共享状态 | 放在 `common/stores/*.svelte.ts`，用 runes 导出 |

共享状态限于：当前用户与令牌、已选座位集合、全局提示。其余一律就近管理。

**已选座位集合是本地交互态**，不写库、不等于已预约；提交时才由后端做原子校验。

## 五、路由与权限

| 事项 | 约定 |
|---|---|
| 路由方案 | 项目自选其一（库或自研 hash），S2 内定稿，全仓统一 |
| 路由守卫 | 需登录的页面在前端做跳转守卫 |
| 二次校验 | 前端守卫只是体验，**服务端必须独立校验角色与资源归属** |
| 角色分入口 | 普通用户与主办方登录后进入各自的入口，不互相暴露菜单 |

## 六、接口调用规范

### 统一响应处理

后端**所有接口 HTTP 状态码恒为 200**，业务状态在响应体的 `code` 中。

| 规则 | 说明 |
|---|---|
| 成功判定 | 只判断 `code === 200` |
| 失败处理 | 其余一律展示 `message` 文案 |
| **禁止** | 禁止依赖 HTTP 状态码做分支（401 也会以 200 返回） |
| 令牌过期 | `code === 401` 时清除本地令牌并跳登录 |
| 登录/注册的 401 | 只展示 `message`，不清令牌、不跳转（见 `docs/contracts/auth.md` §7） |
| 特殊分支 | 请求层：选座提交收到 `409` 时刷新座位状态并提示重选；重复签到 `409` 由核验页展示首次签到时间（§八） |

请求客户端在 `common/api/` 内做一次响应解析与守卫，对外返回 typed 结果；**禁止把接口返回直接断言成目标类型**。

### 错误码常量

前端维护错误码常量表，与后端错误码**逐字一致**，变更时同一次提交内同步。

| code | 含义 |
|---|---|
| 200 | 成功 |
| 400 | 请求或业务规则不允许 |
| 401 | 身份问题 |
| 403 | 权限问题 |
| 404 | 资源不存在 |
| 409 | 状态冲突 |

### 页面状态

每个列表页与详情页必须实现三种状态：加载中、空数据、错误。不允许出现空白无提示的页面。

## 七、3D 选座组件约定

| 事项 | 约定 |
|---|---|
| 数据来源 | 只依赖两个接口：场馆座位静态坐标、该场活动座位动态状态 |
| 布局计算 | 坐标全部由后端给出，**前端不做布局计算**，直接摆放 |
| 状态对齐 | 两个接口按座位编号对齐：坐标决定摆放位置，状态决定颜色 |
| 缓存 | 静态坐标进页面取一次即可缓存；动态状态提交失败后刷新 |
| 开发期 | S2 用本地模拟数据开发，接口就绪后只替换数据来源 |
| 单场馆 | 只有一套坐标，镜头与灯光参数一次调好即可复用 |
| 交互 | 点击座位切换本地已选；已预约座位不可选 |
| 性能 | 100—150 个座位需注意实例化方式，避免逐座位创建独立材质 |

**接口契约在 S2 末冻结**，之后只允许新增字段，不允许改字段含义。

## 八、二维码与核验页

| 事项 | 约定 |
|---|---|
| 二维码渲染 | 用二维码库渲染到画布，内容由后端返回的票号原文（纯字符串，非 URL）给出 |
| 明文票号 | 电子票页必须同时展示明文票号，便于手动核验 |
| 核验通道 | 主办方核验页支持扫码与**手动输入票号**两条通道，手动通道为硬性要求 |
| 重复签到 | 收到 409 时展示首次签到时间，不静默失败 |

## 九、类型规范（严格模式）

| 项 | 要求 |
|---|---|
| 编译器 | 严格模式开启 |
| 索引访问检查 | 建议开启——取座位数组元素时必须处理可能为空的情况 |
| `any` | 一律禁止，含显式与隐式 |
| 忽略注释 | 一律禁止 |
| 非空断言 | 仅限已由路由守卫保证的字段，且需在类型声明处收口，不得散落各处 |
| 组件属性 | 用类型化的属性声明 |
| 接口响应 | 客户端内做解析与守卫后对外返回 typed 结果，禁止直接断言 |
| 组件库组件 | 生成代码不修改；自定义封装在 `common/components/` 内做类型收口 |
| 3D 组件 | 事件与网格参数使用库提供的类型，禁止绕过类型系统传参 |

**检查门槛**：类型检查零错误为合并门槛，未通过不允许合并。
