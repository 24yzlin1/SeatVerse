# SeatVerse · 后端开发规范

> 技术栈：Python 3.13+ / FastAPI / SQLite（标准库 `sqlite3`）
> 类型要求：**严格模式，禁止 `Any`，禁止 `type: ignore`**
> 本规范对齐项目通用分层规范的语言无关部分，语言专属条款已做 Python 等价替换。

---

## 一、总体架构

项目采用**四层架构**，自上而下依赖关系如下：

- **类型定义**：数据行类型、请求/响应 DTO、统一响应结构，供所有层引用。
- **数据访问**：封装数据库连接与 CRUD，只关心 SQL，与业务解耦。
- **业务逻辑**：实现核心业务用例，调用 repos 组装数据，返回普通业务对象；**假定入参已由 scope 校验**。
- **路由控制**：HTTP 入口，负责**参数校验**与响应包装，调用 core 层，**始终返回 HTTP 200**。

**依赖方向**：`main` → `scope` → `core` → `repos` → `types`。

| 层 | 目录 | 核心职责 |
|---|---|---|
| 类型定义 | `app/types/` | 数据行类型、请求/响应 DTO、响应结构 |
| 数据访问 | `app/repos/` | 数据库连接、建表索引、全部 SQL、CRUD |
| 业务逻辑 | `app/core/` | 业务用例、业务规则校验、组装数据 |
| 路由控制 | `app/scope/` | HTTP 适配、参数校验、统一响应包装 |

> 各层只做本职内的事：**参数校验在 `scope`，业务规则在 `core`，SQL 在 `repos`，类型在 `types`**，避免职责交叉。

## 二、目录结构与导入

```
backend/
├── app/
│   ├── types/
│   │   ├── common.py            # 统一响应结构、分页结构
│   │   └── <领域>.py            # 数据行类型 + 请求/响应 DTO
│   ├── repos/
│   │   ├── db.py                # 连接、PRAGMA、事务入口、行映射工具
│   │   └── <领域>.py            # 纯 SQL
│   ├── core/
│   │   ├── common.py            # 业务异常、领域规则工具
│   │   └── <领域>.py            # 业务用例
│   └── scope/
│       ├── common.py            # 校验工具、响应包装、异常处理
│       └── <领域>.py            # 路由与依赖
├── main.py                      # 应用装配入口（中间件、路由、异常处理器；沿用现有入口，不建 index.py）
├── tests/
├── scripts/
│   ├── seed.py                  # 从 JSONL 导入种子数据
│   └── concurrency_test.py      # 并发抢座验收脚本
├── pyproject.toml               # uv 依赖、mypy 配置与 poe 任务（不另建 requirements.txt）
└── .env.example
```

入口沿用 `main.py`；依赖与任务用 uv + `pyproject.toml`，不建 `index.py` / `requirements.txt`。

### 导入规则

- 一律使用**绝对导入**，从 `app.` 起写全路径。
- **禁止用相对导入跨层引用**（即禁止 `from ..core import ...` 这类跨层写法）。
- 同一层内也优先绝对导入，保持全仓一致。

### 扁平与领域子目录

- **初期采用扁平结构**：四层目录下直接放文件，不按领域建子目录。
- 当某层文件超过 6 个或出现明显领域聚集时，可按需拆分子目录，但**必须四层对称拆分**，保持结构可对照。

## 三、统一响应格式

所有接口的 **HTTP 状态码固定为 200**，业务状态通过响应体的 `code` 字段区分。前端通过判断 `code === 200` 识别成功。

### 响应结构

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | 整数 | `200` 成功，其余为错误码 |
| `message` | 字符串 | 可直接展示给用户的中文提示 |
| `payload` | 泛型 | 业务数据；失败时按场景置空或给出最小上下文 |

响应模型定义在 `types/common.py`，使用泛型参数，**禁止把 `payload` 写成 `Any`**。

> **重要**：401、403、404、409 全部以 HTTP 200 返回，只体现在响应体**顶层**的 `code` 字段（不是 `payload.code`）。前端禁止依赖 HTTP 状态码做分支。

### 分页结构

列表响应统一包一层分页：

| 字段 | 类型 | 说明 |
|---|---|---|
| `items` | 数组 | 当前页条目 |
| `total` | 整数 | 总条数 |
| `page` | 整数 | 当前页码，从 1 开始 |
| `pageSize` | 整数 | 每页条数 |

### 错误码

| code | 含义 | 触发场景 |
|---|---|---|
| 200 | 成功 | — |
| 400 | 请求或业务规则不允许 | 参数缺失/类型错/取值非法；场馆编号不是唯一预设场馆；活动已结束或已关闭预约；取消时活动已开始或已结束 |
| 401 | 身份问题 | 未登录、令牌过期、账号或密码错误 |
| 403 | 权限问题 | 角色不足、操作不属于自己的活动或预约（**票号/票据的归属校验除外**，见下文“防枚举例外”） |
| 404 | 资源不存在 | 活动、预约、座位、票号不存在；**票号/票据归属校验失败也归入本码** |
| 409 | 状态冲突 | 座位已被占（并发抢座失败）、重复取消、重复签到 |

场景细分靠 `message` 文案，后端给出可直接展示的中文。请求层的 409 特殊分支只有**选座提交收到 409 时刷新座位状态并提示重选**；核验页的重复签到 409 由该页展示首次签到时间（03 §八）。

**票号类资源的防枚举例外**

`GET /bookings/{id}/ticket`、`GET /tickets/{ticket_code}`、`POST /tickets/verify` 在「票号或预约不属于当前用户」「票不属于本主办方活动」时，**统一返回 `404`**，与「资源不存在」使用同一句 `message`，不返回 `403`：票号是随机串，若 403/404 可区分，等于给出枚举探测的判据。`403` 仅保留给「已登录但角色不足」（如普通用户访问主办方接口）。该例外与 04 号 §3.8、仓库内 `docs/contracts/ticket-qr.md` §4 一致。

后端错误码常量与前端错误码常量**两处必须一致**，同一次提交内同步。

## 四、参数校验与业务逻辑的边界

参数校验**统一收敛在 scope 层**，core 层不再重复校验入参。

| 关注点 | 归属 | 示例 |
|---|---|---|
| 请求体/查询参数的存在性、类型、范围、归一化 | `scope/` | 用户名非空并去空格；活动编号/座位编号为正整数；场馆编号为唯一预设场馆 |
| 业务规则与领域不变量 | `core/` | 邮箱已注册（409）；密码错误（401）；座位已被占（409）；活动已关闭（400）；非本人资源（403；票号/票据的归属校验按 §三 防枚举例外返回 404） |

**约束**

1. 请求体的**结构校验**由请求模型在框架层自动完成，发生在进入函数之前。
2. **业务性校验与归一化**（去空格、正整数范围、场馆合法性、时间先后）仍写在 scope 层，产出 typed DTO。
3. core 层函数的入参是**已校验的 typed DTO**，禁止再接收原始字典，禁止重复做类型断言。
4. 参数不合法统一在 scope 层抛业务异常，由异常处理器转成统一响应。
5. 归一化属于 scope；core 只消费归一化后的值。
6. 请求/响应 DTO 定义在 `types/`，由 scope 与 core 共用，**禁止在 core 内声明响应结构**。
7. `scope/common.py` 提供通用校验工具与响应包装工具。

> core 层**不做**重复的结构校验，但**照常做**业务规则判断：活动是否可预约、座位是否已被占、资源是否归属本人。

## 五、类型规范（严格模式）

### 5.1 工具与开关

全组统一使用**一种**类型检查器（mypy 或 pyright，二选一，不混用），配置写入配置文件，不靠命令行参数传递。

| 开关 | 要求 | 影响 |
|---|---|---|
| 严格模式总开关 | 必开 | 打开绝大部分检查 |
| 禁止未标注的函数 | 开 | 所有函数必须有完整参数与返回类型标注，**含测试脚本** |
| 禁止调用未标注函数 | 开 | 第三方无标注库需补类型存根或本地声明 |
| **禁止显式 `Any`** | 开 | 显式写 `Any` 直接报错 |
| **禁止泛型 `Any`** | 开 | 容器不写泛型参数直接报错 |
| 禁止隐式可选 | 开 | 默认值为空的参数必须显式标为可选 |
| 禁止返回 `Any` | 开 | 返回无类型值直接报错 |
| 未使用的忽略注释报错 | 开 | 多余忽略注释也算错，杜绝随手加 |
| 禁止不完整的定义 | 开 | 部分标注视为未标注 |

> **注意**：mypy 的 `--strict` **不包含**「禁止显式 `Any`」，需单独开启对应开关；pyright 在 strict 下默认包含。统一写进配置文件，避免各人命令不一致。

### 5.2 禁用清单（评审逐条查）

| 禁用项 | 说明 |
|---|---|
| `Any`（显式、隐式、泛型均含） | 一律禁止，含函数返回值与类型别名 |
| `# type: ignore` | 一律禁止。确属第三方库缺陷时，改为在 `types/` 下补最小类型存根，并在合并请求说明理由 |
| 无类型断言绕过检查 | 禁止用类型转换把无类型值直接变成业务类型 |
| 字典下标取值当业务对象 | 边界处必须走显式构造或类型守卫 |
| 裸忽略注释 | 即使需要抑制也必须写明具体错误码，本项目一律禁止 |

### 5.3 类型边界处理（无类型值只在边界出现一次）

| 边界 | 处理方式 | 归属层 |
|---|---|---|
| 请求体与查询参数 | 结构由请求模型自动校验，业务性校验由 scope 校验工具完成，产出 typed DTO | `scope/` |
| 数据库返回值 | `repos/` 内统一做一次「驱动行 → 数据行类型」的**显式映射**，字段逐个取值并校验，对外只暴露 typed 结果 | `repos/` |
| 令牌解析结果 | 鉴权依赖内校验载荷结构并转成 typed 身份对象，禁止业务代码解析令牌 | `scope/` |
| 异常 | 异常处理器内用类型守卫区分业务异常与未知异常；未知异常统一记日志并返回通用错误 | `scope/` |
| 第三方库缺类型存根 | 优先装官方存根包；无存根时在 `types/` 下写最小声明，**不得用 `Any` 兜底** | `types/` |
| 配置读取 | 配置模型内完成类型转换与校验，业务代码只消费 typed 配置对象 | `types/` |

## 六、数据访问层约定

### 6.1 驱动选择

使用**标准库 `sqlite3`**，同步连接，不引入 ORM。

| 理由 | 说明 |
|---|---|
| 贴合分层 | 规范明确 repos 只处理 SQL，ORM 会把查询逻辑上移，破坏分层 |
| 演示机零安装 | `sqlite3` 随 Python 自带，无需编译原生模块，换机风险最低 |
| 类型干净 | ORM 查询结果大量退化为 `Any`，与类型规范冲突；手写行映射可全链路类型明确 |

代价是行结果需手工映射，成本集中在 `repos/db.py` 一处。

### 6.2 连接级约定（必须落在 `repos/db.py`）

| 约定 | 作用 |
|---|---|
| 预写日志模式（WAL） | 读不阻塞写，降低并发演示卡顿 |
| 外键约束开启 | SQLite 默认不检查外键，不开等于外键白建 |
| 锁等待超时（建议 15 秒） | 抢不到写锁时等待而非立刻报错 |
| 行工厂设置 | 使查询结果可按列名取值，便于行映射 |

### 6.3 repos 层纪律

- 只写 SQL 与行映射，**禁止任何业务判断**（不做「活动是否已关闭」之类的判断）。
- **禁止把驱动行对象或原始元组外传给 core 层**；一律转成本项目定义的数据行类型。
- 建表语句与索引集中在建表脚本中，版本化进仓库。
- 查询参数一律使用参数化绑定，**禁止字符串拼接 SQL**。

## 七、事务与并发（最关键的工程点）

### 7.1 三条铁律

| 铁律 | 说明 |
|---|---|
| 禁止行锁写法 | SQLite 没有行级锁语句，相关写法在其上无效或报错 |
| 事务开始即申请写锁 | 关闭驱动的自动事务行为，从第一步就拿写锁，杜绝并发读到旧状态 |
| 条件更新 + 唯一索引兜底 | 把「空闲」写进 UPDATE 的 WHERE 条件，判断受影响行数；同时用唯一索引做最后一道防线 |

### 7.2 预约事务流程

固定在 `core/` 的一个事务内完成五步：

1. 校验活动处于可预约状态（未结束、未关闭）。
2. 创建预约记录。
3. 逐个座位执行条件更新：仅当该座位在该活动中仍为空闲时才改为已预约，判断受影响行数，**不为 1 即视为被抢走**。
4. 写入预约与座位关联记录、生成电子票与票号。
5. 任一步失败则整体回滚，返回 409「座位刚刚被预约，请重新选择」。

多座位预约的「要么全成功要么全失败」由同一事务与回滚保证。取消须由本人、活动开始前且未核验时发起；取消时把关联记录置为无效并把座位状态改回空闲，座位即可被重新预约。

### 7.3 关键索引

| 索引 | 作用 |
|---|---|
| `event_seats(event_id, seat_id)` 唯一 | 同一场活动同一座位只允许一行状态 |
| `booking_seats(event_id, seat_id)` 部分唯一（仅对有效记录生效） | 兜底防重；取消时置为无效，允许座位被重新预约 |
| `tickets(ticket_code)` 唯一 | 票号不可重复 |

### 7.4 同步风格约定

- 端点**一律用同步函数定义**，数据库调用全部同步。框架会把同步端点放到线程池执行，不会阻塞事件循环。
- **严禁异步端点配同步数据库调用**（会阻塞事件循环）。
- 禁止在 `async def` 中出现任何数据库调用。

## 八、路由层约定

| 事项 | 约定 |
|---|---|
| 路由分组 | 按模块分组，统一 `/api` 前缀，不带版本号 |
| 命名 | 路径段用完整单词，禁止缩写；资源名用复数；动作性接口用动词子路径 |
| 鉴权 | 用依赖注入返回 typed 身份对象，**禁止往请求对象上挂无类型属性** |
| 角色守卫 | 用依赖注入声明所需角色，禁止在函数体内手写判断 |
| 响应包装 | 一律经 scope 的响应工具包装，禁止直接返回裸字典 |
| 状态码 | 一律 HTTP 200，业务状态由 `code` 承载 |

### 异常处理

| 异常类型 | 处理 |
|---|---|
| 业务异常 | 转成对应 code 与 message |
| 框架参数校验异常 | 覆写为 400 + 可读文案 |
| HTTP 异常 | 覆写为统一响应体 |
| 唯一约束冲突 | 在业务层映射为对应冲突码（如座位已被占），禁止直接暴露数据库错误 |
| 未知异常 | 记日志，返回通用错误文案，**不回显内部细节** |

## 九、测试约定

| 类型 | 范围 | 工具 |
|---|---|---|
| 单元 | core 层业务规则、scope 层校验工具 | pytest |
| 集成 | 对应用发起真实请求，覆盖预约、取消、权限、异常 | pytest + httpx |
| 并发 | 10 个真并发请求抢同一座位，断言 1 成 9 败 | `scripts/concurrency_test.py` |

**必须覆盖的场景**：两人同时预约、重复提交、取消后重新预约、重复签到、多座位预约失败回滚、非本人操作被拒、已关闭活动不可预约。

## 十、提交与评审清单

每次合并请求需自查：

| # | 检查项 |
|---|---|
| 1 | 类型检查零错误（后端 + 前端） |
| 2 | 无 `Any`、无 `type: ignore`、无裸断言绕过 |
| 3 | 分层未越界：scope 无 SQL、core 无 HTTP、repos 无业务判断 |
| 4 | 响应一律经统一包装，HTTP 恒 200 |
| 5 | 涉及座位的写入走事务，且使用条件更新 + 唯一索引 |
| 6 | 未出现异步端点调用同步数据库 |
| 7 | 数据库返回值已做行映射，无裸行对象外传 |
| 8 | 场馆编号为查库取得，无硬编码常量 |
| 9 | 错误码与前端常量表一致 |
| 10 | 新接口已在自动生成的接口文档中体现 |
