# SeatVerse · 电子票号与二维码契约

> 状态：已冻结 ｜ 负责人：A ｜ 日期：2026-11-06
> 适用：电子票页、票号直达页、主办方核验页，以及票务相关接口
> 依据：01 号《项目策划书》§4、04 号《开发路线图》§3.6—3.7 / §八、05 号《六人分工方案》票务分工
> 说明：本文只冻结票号、二维码内容、权限与异常语义；二维码渲染库由实现阶段选择

---

## 1. 一句话结论

**票号由服务端生成，固定为 20 位 Crockford Base32 字符串；二维码编码内容就是票号原文，不是 URL、不带签名、不带前缀；用户端同时展示明文票号，核验端同时支持扫码与手动输入。**

---

## 2. 票号格式

### 2.1 规范形式

| 项 | 结论 |
|---|---|
| 长度 | 固定 20 个字符 |
| 字符集 | Crockford Base32：`0123456789ABCDEFGHJKMNPQRSTVWXYZ`（排除易混淆的 `I`、`L`、`O`、`U`） |
| 大小写 | 规范形式为**大写**；后端比较前统一转大写 |
| 正则 | `^[0-9A-HJKMNP-TV-Z]{20}$` |
| 示例 | `SV7F3K9Q2M4T8X6B5N2P` |
| 唯一性 | 数据库 `tickets(ticket_code)` 唯一约束；生成冲突时重试 |

### 2.2 生成规则

1. 使用密码学安全随机源（Python `secrets.choice`）逐位生成，不得使用自增编号、时间戳、用户编号、预约编号或它们的拼接。
2. 生成发生在服务端预约事务内，与预约记录、座位关联、票记录同一事务提交；失败整体回滚。
3. 票号一经生成不再改变；取消预约不回收票号，票面状态按派生规则变为 `cancelled`（见 `enums.md` §2.5）。
4. 票号不是登录令牌，不携带任何权限；读取与核验仍须登录并校验归属。

### 2.3 输入归一化

| 场景 | 规则 |
|---|---|
| 页面手动输入 | 去首尾空格、去连字符、转大写后再提交；空值不请求 |
| 路径参数 | 前端 `encodeURIComponent`；后端按去空格、去连字符、转大写后的规范形式比较 |
| 长度或字符集不符 | 不发起核验请求；页面直接提示“票号格式不正确” |
| 比较 | 只比较归一化后的完整 20 位字符串，不做前缀匹配、模糊匹配或大小写敏感匹配 |

## 3. 二维码内容

### 3.1 编码值

**二维码内容严格等于 `ticketCode` 的规范形式。**

```text
SV7F3K9Q2M4T8X6B5N2P
```

| 要求 | 结论 |
|---|---|
| 是否 URL | 否；不得出现 `http://`、`https://`、`/api`、`#` |
| 是否带签名 | 否 |
| 是否带前缀 | 否；不得写成 `SEATVERSE:`、`ticket:` 等 |
| 是否带空白 | 否；不得有前后空格、换行 |
| 字符编码 | UTF-8 |
| 建议纠错级别 | M |
| 静区 | 四周至少 4 个模块 |
| 显示尺寸 | 不小于 240×240 px，保证演示机与手机可扫 |

### 3.2 扫描与核验路径

```
用户票页展示二维码（内容 = ticketCode）
        │
        ├─ 主办方扫码 ──► 解析出字符串 ──► 校验长度/字符集 ──► POST /tickets/verify
        │
        └─ 用户点击票号直达 ──► #/tickets/:code ──► GET /tickets/{code}

摄像头不可用 ──► 手动输入票号 ──► 同一核验接口
```

- 扫码结果必须**先做格式校验再请求**，不得把任意二维码文本直接拼进 URL。
- 扫码得到的字符串按 §2.3 归一化后提交。
- 手动输入是硬性兜底通道，演示机摄像头不可用时必须仍能完成核验。

## 4. 接口与权限

### 4.1 读取电子票

| 接口 | 权限 | 返回 | 非本人/不存在 |
|---|---|---|---|
| `GET /bookings/{id}/ticket` | 登录 + 预约本人 | `Ticket` 对象（完整信封） | 统一 `404` |
| `GET /tickets/{ticket_code}` | 登录 | 与上者同构的 `Ticket` 对象 | 统一 `404` |

- 两个接口返回**同一形状**的 `Ticket`，字段见 `docs/contracts/api.md` §4.3。
- 非本人票、未知票、格式非法票统一返回 `404`，不区分“不存在”和“别人的票”，避免被枚举探测。
- 未登录访问返回 `401`，由请求客户端统一清令牌并跳登录。

### 4.2 核验电子票

| 项 | 结论 |
|---|---|
| 接口 | `POST /tickets/verify` |
| 权限 | 登录 + `organizer`，且活动归属当前主办方 |
| 请求体 | `{ "ticketCode": "SV7F3K9Q2M4T8X6B5N2P" }` |
| 成功返回 | 更新后的完整 `Ticket`，`status = "used"`，`verifiedAt` 非空 |
| 未知票 / 格式非法 / 非本主办方活动的票 | `404`，不区分“不存在”与“不属于本活动” |
| 重复核验 / 已取消 / 活动已取消或已结束 | `409` |
| 角色不足（非 `organizer`） | `403` |
| 未登录 | `401` |

**核验事务要求**

1. 在同一写事务内重查票、预约、活动与座位归属，禁止先查后改。
2. 只有 `booking.status === "reserved"` 且活动未取消、未结束时才允许核验。
3. 写入 `verifiedAt`、`verifiedBy`，更新 `bookings.status = "used"`；票面 `status` 按派生规则得到 `used`，同一事务提交。
4. 重复核验返回 `409`，不得出现“已取消仍签到”。

主办方核验他人活动（或不存在）的票号统一返回 `404`，避免用票号枚举探测；只有“已登录但不是主办方角色”才返回 `403`。

### 4.3 状态与文案

- 票与预约状态字面量见 `docs/contracts/enums.md`。
- 重复核验的 `409` 文案由后端给出可直接展示的中文；前端不自行拼接英文错误。
- 重复核验的 409 文案必须包含该票首次核验时间（03 §8），由后端写入 `message`；核验页原样展示，不静默失败。
- 票号页的 404 文案由后端 `message` 统一给出“票号不存在或无权查看”，前端原样展示，不自行改写（02 §三）。

## 5. 前端展示与降级

### 5.1 票面

电子票页至少展示五项，且全部来自接口原始响应：

1. 活动名
2. 场馆
3. 场次时间
4. 座位（`label`，如“3排12号”）
5. 明文票号（等宽字体大号展示 + 复制按钮）

复制使用 `navigator.clipboard.writeText(ticketCode)`；失败时降级为选中明文票号供手动复制。

### 5.2 二维码渲染失败

- `try/catch` 捕获渲染异常，原位显示“二维码生成失败，请出示票号”并展示明文票号。
- 不得因二维码失败导致整页白屏或隐藏票号。
- 断网时二维码仍应正常显示，因为内容完全来自已加载的票数据。

### 5.3 状态样式

| 票状态 | 展示 |
|---|---|
| `reserved` | 正常票面 + “待核验”徽标 |
| `used` | 灰度 + 对角水印 + “已核验”徽标；二维码仍保留，便于人工核对 |
| `cancelled` | 标注“已失效”；不得作为有效票出示或核验 |

---

## 6. 异常与边界

| 场景 | 处理 |
|---|---|
| 票号含空格、连字符、小写 | 归一化后接受 |
| 票号长度不对或含非法字符 | 前端拦截，提示格式错误；后端收到时返回 `404` |
| 二维码内容为 URL 或被篡改 | 视为非法票号，不请求核验或返回 `404` |
| 同一票并发核验 | 条件更新保证只有一次成功，其余 `409` |
| 预约已取消 | `GET` 返回票面并标注失效；核验返回 `409` |
| 活动已取消或已结束 | 票面可查看；核验返回 `409` |
| 票号属于他人 | `404`，文案与“不存在”一致 |

## 8. 验收清单

| # | 操作 | 预期 |
|---|---|---|
| 1 | 手机相机扫描票页二维码 | 读出的字符串恰好等于明文票号，不含 `http` |
| 2 | 断网后打开票页 | 二维码仍正常显示 |
| 3 | 点击复制按钮后粘贴 | 内容等于票号，无空格、无前缀、无换行 |
| 4 | 手动输入小写或带连字符的票号 | 归一化后能查到本人票 |
| 5 | 输入他人票号 | 显示“票号不存在或无权查看” |
| 6 | 同一票连续核验两次 | 第一次成功，第二次 `409`，票状态保持 `used` |
| 7 | 取消预约后打开票页 | 显示“已失效”，核验返回 `409` |
